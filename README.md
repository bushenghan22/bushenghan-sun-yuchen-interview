## 前言:这是什么

2026 年 10 月 9 日,YouTube 频道 **Alan Shao(邵艾伦)** 发布了一期 4 小时 22 分的访谈,嘉宾是**孙宇晨**。题目叫《对话孙宇晨:年轻人如何抓住AI时代的机会?》。

四小时二十分。这个长度,绝大多数人听不完,更别说记住。

所以我把这一整场对话**从头到尾整理了一遍**,写成三份文档——**内容完全一样,只是详细程度不同**,你可以按自己的时间和兴趣挑一份读。

**先说最重要的一件事:三份文档都是二手整理,不是原话。**

那期视频没有字幕,整理过程中用软件把语音转成了文字,但软件会听错——人名、公司名、专业词汇,错得不少。所以文档里凡是加引号的句子,都只能理解成"**意思大致如此**",**不能当成他的原话引用**。

另外,文中所有观点**都属于孙宇晨和alan本人**,不代表整理者的立场。涉及投资、健康、理财、用药的部分,请务必自己独立判断,不要因为看了这份整理就做决定。

## 关于孙宇晨,先给不了解的读者一句话

他是中国互联网和加密货币领域争议很大的公众人物,早年创业,后来做区块链,现居海外。这场对话里他谈的不只是商业,还包括健身、健康、怎么用 AI、怎么看待人生选择——**这也是它值得被整理的原因:它不只是一场商业访谈。**

需要提醒一句:他在视频简介里挂了商业推广链接。所以当他讲到某些具体领域时,你听到的**可能同时是一个推销者的话**,这一点在读的时候要留个心眼。整理者在文档里已经把这些段落标了出来。

## 这份整理和网上那些"AI 总结"有什么不一样

网上的访谈总结,大多是机器把话转成文字、再压缩成要点,发出来就完事。

这份东西多做了三件事——**因为我不放心机器转出来的稿子**:

**第一,把机器听错的地方,一条条找出来改了。**

不夸张地说,错得比想象中多。整场对话的核心词之一"**薄肌**"(指不过度增肌的精瘦体型),被软件从头到尾认成了"**搏击**",出现 171 次;南唐后主"**李煜**"被认成了"**李玉**";"**长鑫存储**"成了"**长青存储**"。我列了一张表(18 项),把每一处错在哪、为什么这么改、依据是什么,全部写清楚,附在每份文档末尾。

**第二,他说的一些事实,我去查了。**

不是听什么信什么。举两个例子:

- 他说 SWIFT(全球银行间的跨境支付系统)是"1955 年"发明的——**实际是 1973 年**。
- 他说数据标注公司 Scale AI"卖给 Facebook 了"——**实际不是收购,是 Meta 2025 年花 143 亿美元买了它 49% 的股份**。

查得到证据的,我在文档里标了;查不到的(他的个人经历、内部数字、主观判断),我就按"转述"处理,不替他背书。

**第三,把"哪些话有道理、哪些话要打折扣"分开列了。**

孙宇晨很会讲——比喻用得好,气势也很足。但**说得漂亮不等于说得对**。所以精读版里专门做了一张表,把他论证里的"修辞夸张""用专业名词给经验判断镀金""前后不一致""商业推广语境"这些挑出来,分门别类。

也有"值得听的部分":他讲主动体检、讲"遇到跟自己想法冲突的信息要先假设对方可能对",这些是实在的。

**整理者的立场是:离它远一点看,而不是替他复述一遍。**

## 一个可能让你意外的发现

精读版里指出了一件事:这场访谈的**主持人,一年前曾给孙宇晨投过简历、想加入他的团队**——这件事在访谈结尾由主持人自己说了出来。

这意味着什么?这意味着这不是一次中立的采访,而是**一个求职者,在和自己想去的老板对话**。

这就解释了为什么四小时里**没有一个真正尖锐的质疑**——不问他商业上的争议,不问那些具体的财务数字,不追问那些含糊的地方。主持人问得其实不差,有几个问题相当有力,但**整体上,这是一场"双方都很舒服"的对话**。

知道这一点,你听进去的每一句话,分量都会不一样。这也是这份整理最值得你看的地方之一。

## 制作方法(完整技术细节)

**不关心技术可以跳过这一节。** 下面是完整的制作管线,写给想要复刻或审查这套流程的人。

### 第一步:拿到音频

视频源在 YouTube 与 B 站均**没有任何字幕**——手动字幕和自动字幕都是空的。所以没有现成文字稿可用,必须自己从音频转。

下载音频轨(opus / 48kHz),统一转成 **16kHz 单声道** PCM——这是语音识别模型的标准输入格式。转换用 `ffmpeg`:

```
ffmpeg -i input.webm -ar 16000 -ac 1 -c:a pcm_s16le output.wav
```

**为什么强调本地:** 整条管线在本地跑,音频**没有上传到任何云端服务**。4 小时 22 分的素材,涉及隐私与版权,本地处理是前提。

### 第二步:语音转文字(ASR)

转写引擎是 **`faster-whisper`**(Whisper 的 CTranslate2 实现),模型用 **`large-v3`**——这是目前中文识别效果最好的开源模型之一。

关键参数:

| 参数                           | 取值          | 作用                       |
| ---------------------------- | ----------- | ------------------------ |
| `language`                   | `zh`        | 锁定中文,避免语种误判              |
| `beam_size`                  | `5`         | 束搜索宽度,提升准确率              |
| `vad_filter`                 | `True`      | 语音活动检测,自动跳过静音段           |
| `condition_on_previous_text` | `False`     | **关键**:关闭上文依赖,防止错误跨段累积传播 |
| `initial_prompt`             | 提示用简体中文并加标点 | 引导输出格式                   |

**性能:** 在单张消费级 GPU 上,转写速度约为播放速度的 **9.7 倍**——4 小时 22 分的音频,大约 27 分钟跑完。输出 8,914 段,合计约 **70,867 字**纯文本。

**踩过的坑(Windows + NVIDIA):** CTranslate2 需要 `cublas64_12.dll` / `cudnn64_9.dll`,但 pip 装的 `nvidia-*-cu12` 包会把它们放在 `site-packages/nvidia/*/bin` 下,**这个路径不在默认的 DLL 搜索路径里**。不手动注册就会报 "cublas64_12.dll is not found"。解法是用 `os.add_dll_directory()` 把这些目录注册进去。

另一个坑:`faster-whisper 1.2.1` 与 `PyAV 19` 不兼容(`metadata_errors` 参数被移除),不能走 PyAV 解码音频,所以音频统一由 `ffmpeg` 预处理后再自行读入。

### 第三步:说话人分离(谁在说话)

一场访谈有两个人在对话,但语音转文字的输出**不区分谁说的**。所以补了一个说话人分离(Diarization)环节,用 **`sherpa-onnx`** 跑:

- **分段模型:** `pyannote-segmentation-3-0`
- **声纹嵌入模型:** `3dspeaker` 的 CAM++ 中文模型
- **聚类:** 快速聚类,阈值 0.5

输出每一段的时间区间与说话人编号,再与 ASR 的逐段结果**按时间重叠量匹配**——取重叠最大的说话人作为该段的归属。这一步让"主持人问 / 嘉宾答"的结构能被自动识别出来。

### 第四步:按章节切分

视频简介里**自带完整的 39 条章节时间轴**。整理时直接采用这个官方时间轴切分,而不是自己重新划段——这样文档的每一节都能**对应回视频的真实位置**,方便读者按时间点回看原片。

### 第五步:逐节撰写(三档粒度)

同一份底稿,写了三种详细程度:

- **话题总结** —— 每节 2~4 段要点
- **深度精读版** —— 每节含时间定位、场景还原、原话摘录、逐条分析与质疑
- **深度转述版** —— 逐节完整重述内容

### 第六步:两轮事实核查

这一步是整个整理里最花时间的部分:

1. **回原稿比对** —— 所有数字、人名、专名回原始转写逐条核对,防止在归纳时抄错
2. **外部信源核证** —— 对受访者陈述中可外部验证的部分,查证并标注结果(例如 SWIFT 成立年份、Scale AI 交易性质)

同时列出**转写校正对照表**,把机器识别错误逐条修正并给出依据。

### 一句话小结

**下载音频 → 16kHz 归一化 → faster-whisper large-v3 转写 → sherpa-onnx 说话人分离 → 时间轴对齐 → 章节切分 → 逐节撰写 → 两轮核查 → 输出三档读本。**

全程本地,无云端。
